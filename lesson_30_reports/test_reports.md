# Lesson 30. Test Reports: pytest-html и Allure

## Зачем нужны отчёты о тестах

Обычный вывод pytest в терминале — это текстовый результат выполнения тестов:

```text
5 passed, 2 failed
```

Для локальной разработки этого часто достаточно, но такой формат становится неудобным, когда:

* тесты запускаются в CI/CD и результат нужно анализировать вне консоли;
* отчёт должны видеть менеджеры, заказчики или другие участники команды;
* нужно быстро определить, какой тест упал и по какой причине;
* необходимо посмотреть параметры теста, шаги, логи, скриншоты или ответы API;
* требуется хранить и сравнивать результаты нескольких запусков.

Для создания отчётов в Python-проектах часто используются два инструмента:

* **pytest-html** — простой HTML-отчёт с результатами pytest;
* **Allure** — более функциональный интерактивный отчёт с шагами, вложениями, группировкой и историей запусков.

---

## 1. pytest-html

`pytest-html` — плагин для pytest, который создаёт HTML-отчёт по результатам выполнения тестов.

### Установка

```bash
pip install pytest-html
```

### Запуск с генерацией отчёта

```bash
pytest --html=report.html
```

После завершения тестов будет создан файл `report.html`, который можно открыть в браузере.

Чтобы получить автономный HTML-файл со встроенными стилями и ресурсами, используется дополнительный флаг:

```bash
pytest --html=report.html --self-contained-html
```

Такой файл удобнее передавать другим людям или сохранять как артефакт в CI/CD.

### Настройка через `pytest.ini`

Чтобы не указывать параметры при каждом запуске, их можно добавить в конфигурационный файл `pytest.ini`:

```ini
[pytest]
addopts = --html=report.html --self-contained-html
```

После этого достаточно выполнить:

```bash
pytest
```

Отчёт будет генерироваться автоматически при каждом запуске тестов.

### Структура отчёта

Стандартный отчёт `pytest-html` обычно содержит:

* **Environment** — информацию об окружении, версиях Python, pytest и установленных плагинах;
* **Summary** — общее количество passed, failed, skipped и других результатов;
* **Results** — таблицу с результатами отдельных тестов;
* время запуска и продолжительность выполнения тестов;
* traceback и сообщение об ошибке для упавших тестов.

В отличие от Allure, `pytest-html` не предоставляет полноценную встроенную историю запусков и сложные интерактивные графики.

### Добавление собственного CSS

Внешний вид отчёта можно изменить с помощью собственного CSS-файла:

```bash
pytest --html=report.html --css=style.css
```

Также параметр можно добавить в `pytest.ini`:

```ini
[pytest]
addopts = --html=report.html --self-contained-html --css=style.css
```

На практике стандартного оформления обычно достаточно, поэтому собственные стили используются нечасто.

### Добавление вложений

Скриншоты, текст, ссылки и другие данные не добавляются в `pytest-html` автоматически.

Для этого используются специальные hooks и extras, предоставляемые плагином. Например, скриншот, созданный Selenium или Playwright, необходимо отдельно прикрепить к результату теста.

Следовательно, само наличие скриншота в проекте ещё не означает, что он появится в HTML-отчёте.

### Плюсы pytest-html

* Простая установка через `pip`.
* Быстрая настройка.
* HTML-отчёт создаётся сразу после выполнения тестов.
* Не требует отдельной программы для просмотра отчёта.
* Подходит для небольших проектов и локальной отладки.
* Можно сохранять как артефакт в CI/CD.
* Поддерживает добавление собственных стилей и вложений.

### Минусы pytest-html

* Ограниченная группировка тестов.
* Нет полноценной встроенной истории запусков.
* Нет развитой системы шагов и категорий.
* Вложения требуют дополнительной настройки.
* Меньше возможностей для анализа результатов по сравнению с Allure.

## 2. Allure

Allure — инструмент для создания подробных интерактивных отчётов о тестировании.

Allure позволяет:

* группировать тесты по функциональности и сценариям;
* отображать шаги выполнения теста;
* добавлять логи, скриншоты, файлы и ответы API;
* указывать severity тестов;
* добавлять ссылки на задачи, дефекты и документацию;
* отображать параметры тестов;
* хранить историю запусков;
* интегрировать отчёты с Jenkins и другими CI/CD-инструментами.

## Архитектура Allure

Работа с Allure состоит из двух этапов:

1. Во время запуска pytest создаются сырые данные в папке `allure-results`.
2. Allure CLI преобразует эти данные в интерактивный HTML-отчёт.

То есть Python-пакет `allure-pytest` собирает результаты, а Allure CLI генерирует и открывает отчёт.

---

## Установка Allure CLI

Одной установки Python-пакета недостаточно. Дополнительно требуется установить отдельный Allure CLI.

Для классического Allure CLI также требуется Java. При установке через пакетный менеджер нужная зависимость может быть установлена автоматически, но наличие Java всё равно следует проверить.

### Windows — через Scoop

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Invoke-RestMethod -Uri https://get.scoop.sh | Invoke-Expression
scoop install allure
```

### macOS — через Homebrew

```bash
brew install allure
```

Если Homebrew ещё не установлен:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

### Linux — Ubuntu/Debian

Способ установки может зависеть от используемого дистрибутива и версии Allure. После установки необходимо проверить доступность команд `java` и `allure`.

### Проверка Java

```bash
java -version
```

### Проверка Allure CLI

```bash
allure --version
```

Если команда не найдена сразу после установки, терминал необходимо перезапустить.

## Установка Python-пакета

Для интеграции Allure с pytest устанавливается пакет:

```bash
pip install allure-pytest
```

После установки pytest сможет сохранять результаты тестов в формате Allure.

## Основные декораторы Allure

Allure предоставляет декораторы для добавления метаданных к тестам.

| Декоратор                    | Назначение                                            |
| ---------------------------- | ----------------------------------------------------- |
| `@allure.epic("...")`        | Крупное направление или часть продукта                |
| `@allure.feature("...")`     | Функциональность, которую проверяет тест              |
| `@allure.story("...")`       | Более узкий сценарий внутри функциональности          |
| `@allure.title("...")`       | Понятное название теста в отчёте                      |
| `@allure.description("...")` | Подробное описание теста                              |
| `@allure.severity(...)`      | Уровень критичности теста                             |
| `@allure.issue("...")`       | Ссылка или идентификатор связанного дефекта           |
| `@allure.link("...")`        | Произвольная ссылка на документацию или другой ресурс |
| `@allure.testcase("...")`    | Ссылка на тест-кейс                                   |
| `@allure.step("...")`        | Отдельный шаг выполнения теста                        |

---

## Уровни severity

Severity показывает критичность проверяемой функциональности.

Доступны следующие уровни:

```python
allure.severity_level.BLOCKER
allure.severity_level.CRITICAL
allure.severity_level.NORMAL
allure.severity_level.MINOR
allure.severity_level.TRIVIAL
```

Пример:

```python
import allure


@allure.severity(allure.severity_level.CRITICAL)
def test_user_login():
    assert True
```

В отчёте будет видно, что тест проверяет критически важную функциональность.

---

## Пример параметризованного теста с Allure

```python
import allure
import pytest


@allure.feature("Суммирование")
@allure.story("Суммирование списка чисел")
@allure.title("Проверка суммы чисел: {input_data}")
@pytest.mark.parametrize(
    "input_data, expected_output",
    [
        ([1, 2, 3], 6),
        ([-1, 0, 1], 0),
        ([10, 20, 30], 60),
    ],
)
def test_sum(input_data, expected_output):
    assert sum(input_data) == expected_output
```

Для каждого набора параметров pytest создаст отдельный результат, а Allure покажет переданные значения в отчёте.

## Использование `@allure.step`

Декоратор `@allure.step` удобно использовать для функций, которые представляют отдельные действия.

```python
import allure


@allure.step("Складываем числа {a} и {b}")
def add_numbers(a, b):
    return a + b


@allure.feature("Арифметика")
@allure.story("Сложение чисел")
def test_add_numbers():
    result = add_numbers(2, 3)

    assert result == 5, f"Ожидалось: 5, Получено: {result}"
```

В Allure-отчёте появится отдельный шаг:

```text
Складываем числа 2 и 3
```

Значения аргументов можно подставлять в название шага через фигурные скобки.

---

## Использование `allure.step` как контекстного менеджера

Если отдельная функция не нужна, шаг можно создать непосредственно внутри теста:

```python
import allure


def add_numbers(a, b):
    return a + b


@allure.feature("Арифметика")
@allure.story("Сложение чисел")
def test_add_numbers():
    with allure.step("Вызываем add_numbers с аргументами 2 и 3"):
        result = add_numbers(2, 3)

    with allure.step("Проверяем полученный результат"):
        assert result == 5, f"Ожидалось: 5, Получено: {result}"
```

Такой подход удобно использовать для разделения теста на логические этапы.

## Добавление вложений

К результату теста можно прикреплять:

* текст;
* JSON;
* HTML;
* скриншоты;
* логи;
* ответы API;
* произвольные файлы.

### Добавление текста

```python
import allure


def test_example():
    response_text = '{"status": "ok"}'

    allure.attach(
        response_text,
        name="API response",
        attachment_type=allure.attachment_type.JSON,
    )

    assert True
```

### Добавление скриншота Playwright

```python
import allure


def test_page(page):
    page.goto("https://example.com")

    screenshot = page.screenshot()

    allure.attach(
        screenshot,
        name="Page screenshot",
        attachment_type=allure.attachment_type.PNG,
    )
```

Скриншот будет доступен внутри результата соответствующего теста.

## Генерация Allure-отчёта

### Шаг 1. Запуск тестов и сбор результатов

```bash
pytest --alluredir=allure-results
```

После выполнения тестов появится папка:

```text
allure-results/
```

В ней находятся JSON-файлы и вложения, необходимые для построения отчёта.

Это ещё не готовый HTML-отчёт.

### Шаг 2. Быстрый просмотр отчёта

```bash
allure serve allure-results
```

Команда:

1. временно генерирует отчёт;
2. запускает локальный сервер;
3. открывает отчёт в браузере.

После остановки команды временно созданный отчёт обычно удаляется.

### Генерация постоянного отчёта

Чтобы создать отдельную папку с готовым отчётом:

```bash
allure generate allure-results -o allure-report --clean
```

Где:

* `allure-results` — сырые результаты pytest;
* `allure-report` — готовый HTML-отчёт;
* `--clean` — очищает старый отчёт перед созданием нового.

После этого отчёт можно открыть командой:

```bash
allure open allure-report
```

## Структура Allure-отчёта

### Overview

Главная страница отчёта содержит:

* общее количество тестов;
* количество passed, failed, broken и skipped;
* продолжительность запуска;
* информацию о suite, feature и severity;
* сводные графики.

### Categories

Тесты группируются по типам проблем, например:

* ошибки продукта;
* ошибки тестовой инфраструктуры;
* упавшие assertions;
* сломанные тесты.

Категории можно дополнительно настраивать.

### Suites

Тесты отображаются в структуре, основанной на тестовых файлах, классах и функциях.

Для каждого теста можно посмотреть:

* статус;
* продолжительность;
* параметры;
* шаги;
* вложения;
* traceback;
* сообщения об ошибках.

### Behaviors

Тесты группируются по бизнес-функциональности с помощью:

* `@allure.epic`;
* `@allure.feature`;
* `@allure.story`.

Это позволяет смотреть отчёт не только по структуре файлов, но и по функциональным областям приложения.

### Graphs

Раздел содержит графики:

* статусов тестов;
* severity;
* продолжительности;
* категорий;
* повторных запусков;
* распределения тестов по suite.

---

## История запусков

Allure может отображать изменения результатов между несколькими запусками:

* тест всегда проходит;
* тест начал падать;
* тест был исправлен;
* тест нестабилен;
* тест запускался повторно.

Однако история не появляется автоматически только из-за нескольких локальных запусков.

Для её сохранения данные из папки `history` предыдущего отчёта необходимо передавать в результаты следующего запуска. В CI/CD это обычно настраивается через Jenkins или другой CI-инструмент.

---

## Статусы тестов в Allure

В Allure используются следующие основные статусы:

* **Passed** — тест выполнен успешно;
* **Failed** — проверка завершилась неуспешно, например упал `assert`;
* **Broken** — тест не смог корректно выполниться из-за ошибки в коде теста или инфраструктуре;
* **Skipped** — тест был пропущен;
* **Unknown** — Allure не смог определить корректный статус результата.

Разница между `Failed` и `Broken` помогает отделить возможный дефект продукта от проблемы в автотесте или тестовом окружении.

## Плюсы Allure

* Подробный интерактивный отчёт.
* Поддержка шагов теста.
* Отображение параметров параметризованных тестов.
* Возможность добавлять логи, скриншоты, ответы API и другие вложения.
* Группировка по epic, feature и story.
* Указание severity.
* Поддержка истории запусков.
* Интеграция с Jenkins и другими CI/CD-инструментами.
* Поддержка разных языков и тестовых фреймворков.
* Возможность добавлять ссылки на тест-кейсы, дефекты и документацию.

## Минусы Allure

* Настройка сложнее, чем у `pytest-html`.
* Требуется отдельный Allure CLI.
* Для классического Allure CLI требуется Java.
* Результаты и готовый отчёт хранятся в разных папках.
* Историю запусков необходимо настраивать отдельно.
* Для эффективного отчёта тесты нужно правильно размечать шагами и метаданными.

## pytest-html и Allure — сравнение

| Характеристика      | pytest-html                        | Allure                                           |
| ------------------- | ---------------------------------- | ------------------------------------------------ |
| Установка           | Только Python-пакет через `pip`    | Python-пакет, Allure CLI и Java                  |
| Создание результата | HTML создаётся сразу после тестов  | Сначала создаются сырые данные, затем HTML-отчёт |
| Формат              | Простой HTML-отчёт                 | Интерактивный отчёт                              |
| Шаги теста          | Нет полноценной встроенной системы | Есть `@allure.step` и `allure.step`              |
| Вложения            | Возможны через hooks и extras      | Встроенная поддержка                             |
| Группировка         | В основном по структуре pytest     | Epic, feature, story, suite                      |
| История запусков    | Нет полноценной встроенной истории | Поддерживается при дополнительной настройке      |
| Severity            | Нет встроенной системы             | Поддерживается                                   |
| CI/CD               | Можно сохранять HTML как артефакт  | Есть интеграции с Jenkins и другими CI/CD        |
| Сложность настройки | Низкая                             | Средняя                                          |
| Когда использовать  | Небольшой проект или простой отчёт | Командный проект, CI/CD и подробный анализ       |

---

## Итог

`pytest-html` подходит, когда нужен простой и быстро создаваемый HTML-отчёт без сложной настройки.

Allure стоит использовать, когда необходимы:

* подробные шаги тестов;
* вложения;
* группировка по функциональности;
* severity;
* параметры;
* ссылки на задачи и тест-кейсы;
* история запусков;
* интеграция с CI/CD.

Для небольшого учебного проекта может быть достаточно `pytest-html`. Для полноценного AQA-проекта и CI/CD чаще выбирают Allure.
