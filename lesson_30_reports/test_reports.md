# Lesson 30. Test Reports: pytest-html и Allure

## Зачем нужны отчёты о тестах

Обычный вывод pytest в терминале — это просто текст (`5 passed, 2 failed`). Такого достаточно
для локальной разработки, но неудобно, когда:

- тесты гоняются в CI/CD и результат нужно смотреть не в консоли;
- отчёт должны видеть не-технические люди (менеджер, заказчик);
- нужно быстро найти, какой именно тест упал и почему, не листая логи.

Отсюда два инструмента: **pytest-html** (простой, один HTML-файл) и **Allure** (мощный отчёт
с историей, группировкой и вложениями).

---

## 1. pytest-html — коротко

### Установка

```bash
pip install pytest-html
```

### Настройка через `pytest.ini`

Чтобы не указывать флаг каждый раз при запуске, путь к отчёту можно зафиксировать в конфиге:

```ini
[pytest]
addopts = --html=report.html
```

### Запуск с генерацией отчёта

```bash
pytest --html=report.html
```

После прогона появляется файл `report.html` — его можно открыть в браузере.

### Стилизация (CSS)

Отчёт можно кастомизировать через свой CSS-файл, подключив его через `<link>` в `<head>`
итогового HTML. На практике это нужно редко — сама по себе разметка отчёта уже достаточно
читаема.

### Структура отчёта

- **Dashboard** — последний результат прогона, график истории запусков, список тестов по файлам.
- Тесты сгруппированы по файлам, есть блок с параметрами запуска и временем выполнения.
- Если тесты писали скриншоты (например, через Selenium), они тоже попадают в отчёт.

### Плюсы и минусы pytest-html

**Плюсы:**
- Просто ставится через `pip`, не требует дополнительной инфраструктуры.
- Готовый HTML-файл сразу после прогона — ничего дополнительно генерировать не нужно.
- Можно настраивать внешний вид через CSS.
- Умеет показывать сложные структуры данных (списки, объекты Python) в отчёте.

**Минусы:**
- Ограниченный функционал по сравнению с более серьёзными инструментами: нет генерации
  по-настоящему динамических отчётов и возможности добавлять произвольные метаданные.

## 2. Allure — подробно

Allure — куда более функциональный инструмент: группировка тестов по фичам/сценариям, шаги
внутри теста, вложения (логи, respons'ы, скриншоты), интеграция с Jenkins и историей прогонов.

### Установка Allure CLI

Важно: в отличие от pytest-html, здесь мало поставить pip-пакет — нужен ещё отдельный **Allure
CLI**, который генерирует отчёт из "сырых" данных, собранных во время прогона.

**Windows (через Scoop):**
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Invoke-RestMethod -Uri https://get.scoop.sh | Invoke-Expression
scoop install allure
```

**macOS (через Homebrew):**
```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install allure
```

**Linux (Ubuntu/Debian):**
```bash
sudo apt-add-repository ppa:qameta/allure
sudo apt update
sudo apt install allure
```
Для Linux дополнительно нужна установленная Java с настроенной переменной `JAVA_HOME`, после
чего терминал нужно перезапустить.

Проверка установки на любой ОС:
```bash
allure --version
```

### Установка Python-пакета

```bash
pip install allure-pytest
```

### Декораторы Allure

Allure добавляет набор декораторов, которые обогащают отчёт метаданными:

| Декоратор | Назначение |
|---|---|
| `@allure.feature("...")` | Функциональность, которую проверяет тест — группировка в отчёте по фичам |
| `@allure.story("...")` | Более узкий сценарий внутри фичи — детальная группировка |
| `@allure.title("...")` | Заголовок теста в отчёте (вместо имени функции) |
| `@allure.description("...")` | Описание теста |
| `@allure.issue("...")` | Ссылка на тикет (например, в Jira), связанный с тестом |
| `@allure.link("...")` | Произвольная ссылка на документацию/ресурс |
| `@allure.step("...")` | Шаг внутри теста — делает отчёт пошаговым и понятным |

### Пример теста с Allure

```python
import pytest
import allure


@allure.feature("Суммирование")
@pytest.mark.parametrize("input_data, expected_output", [
    ([1, 2, 3], 6),
    ([-1, 0, 1], 0),
    ([10, 20, 30], 60)
])
def test_sum(input_data, expected_output):
    assert sum(input_data) == expected_output


@allure.feature("Преобразование строк")
@pytest.mark.parametrize("input_string, expected_output", [
    ("hello", "HELLO"),
    ("world", "WORLD")
])
def test_uppercase(input_string, expected_output):
    assert input_string.upper() == expected_output
```

Пример использования `@allure.step` — оборачиваем логическую часть теста в отдельный шаг,
который будет виден в отчёте отдельной строкой:

```python
import allure


def add_numbers(a, b):
    """Функция, складывающая два числа."""
    return a + b


@allure.feature("Арифметика")
def test_add_numbers():
    @allure.step("Вызываем функцию add_numbers с аргументами 2 и 3")
    def add_numbers_step():
        return add_numbers(2, 3)

    result = add_numbers_step()
    assert result == 5, f"Ожидалось: 5, Получено: {result}"
```

### Генерация и просмотр отчёта

```bash
# Прогон тестов со сбором "сырых" данных Allure
pytest --alluredir=allure-report

# Поднять локальный сервер и открыть отчёт в браузере
allure serve allure-report
```

### Структура Allure-отчёта

- **Overview** — сьюты (тестовые файлы), сортировка по фичам (`@allure.feature`), категории
  по типу дефектов.
- **Categories** — упавшие тесты, сгруппированные по типу ошибки; справа — вкладка *Retries*
  с историей перезапусков конкретного теста.
- **Suites** — тесты, разбитые по файлам; справа видно шаги теста, добавленные через
  `@allure.step`.
- **Graphs** — разные визуальные графики; на практике для повседневной работы редко нужны,
  но иногда их любят показывать заказчикам.

### Плюсы и минусы Allure

**Плюсы:**
- Кроссплатформенный, интегрируется с разными языками и фреймворками тестирования.
- Детальный интерактивный отчёт: стек-трейсы, параметры тестов, вложения (файлы, скриншоты).
- Гибкая настройка внешнего вида, стилизации, группировки тестов по категориям.
- Расширяемость через систему плагинов.
- Официальная интеграция с Jenkins — отчёт можно смотреть прямо в CI/CD.

**Минусы:**
- Сложнее в настройке, чем pytest-html: требует отдельного CLI (и Java на Linux), а не только
  pip-пакета.

### pytest-html vs Allure — сводка

| | pytest-html | Allure |
|---|---|---|
| Установка | только `pip` | `pip`-пакет + отдельный Allure CLI (+ Java на Linux) |
| Формат результата | один HTML-файл сразу | сырые данные → отдельная генерация отчёта |
| Детализация | базовая (таблица результатов) | шаги, вложения, история, категории дефектов |
| Интеграция с CI/CD | простая, но менее наглядная | официальный плагин под Jenkins |
| Когда достаточно | маленький проект, локальный дебаг | командная работа, CI/CD, нужна история прогонов |
