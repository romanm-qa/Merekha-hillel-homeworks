# Lesson 13. Логирование (Logging)

## Что такое логирование?

Логирование — это процесс записи информации о работе программы.

В отличие от `print()`, логи можно:

- сохранять в файл;
- выводить в консоль;
- фильтровать по уровню важности;
- анализировать после завершения работы программы.

Логирование широко используется в автоматизации тестирования для анализа выполнения тестов и поиска ошибок.

---

# Импорт модуля

```python
import logging
```

`logging` — встроенный модуль Python для создания логов.

---

# Базовая настройка логирования

```python
logging.basicConfig(
    filename="example.log",
    level=logging.DEBUG,
    format="%(asctime)s - %(levelname)s - %(message)s"
)
```

`basicConfig()` используется для первоначальной настройки логирования и обычно вызывается **один раз** за всё приложение.

---

# Параметры basicConfig()

## filename

```python
filename="example.log"
```

Указывает файл, в который будут записываться логи.

Если файла не существует, Python создаст его автоматически при первой записи.

---

## level

```python
level=logging.DEBUG
```

Определяет минимальный уровень логирования.

Доступные уровни:

```
DEBUG
INFO
WARNING
ERROR
CRITICAL
```

Если указать:

```python
level=logging.WARNING
```

в лог попадут только сообщения уровней:

```
WARNING
ERROR
CRITICAL
```

---

## format

```python
format="%(asctime)s - %(levelname)s - %(message)s"
```

Определяет формат записи каждой строки лога.

Пример:

```
2026-07-05 17:06:05 - INFO - Пользователь успешно авторизовался
```

Где:

- `%(asctime)s` — дата и время;
- `%(levelname)s` — уровень логирования;
- `%(message)s` — текст сообщения.

---

# Методы логирования

```python
logging.debug("DEBUG message")
logging.info("INFO message")
logging.warning("WARNING message")
logging.error("ERROR message")
logging.critical("CRITICAL message")
```

Каждый метод записывает сообщение соответствующего уровня.

---

# Уровни логирования

| Уровень | Назначение |
|---------|------------|
| DEBUG | Подробная информация для отладки |
| INFO | Информация о нормальной работе программы |
| WARNING | Предупреждение, программа продолжает работать |
| ERROR | Произошла ошибка |
| CRITICAL | Критическая ошибка |

---

# Почему уровни пишутся большими буквами?

```python
logging.DEBUG
logging.INFO
logging.ERROR
```

Это **константы**.

По соглашению Python константы пишутся заглавными буквами (`UPPER_CASE`).

Методы пишутся маленькими буквами:

```python
logging.debug()
logging.info()
logging.error()
```

---

# Внутренние значения уровней

На самом деле каждому уровню соответствует число:

| Уровень | Значение |
|---------|---------:|
| DEBUG | 10 |
| INFO | 20 |
| WARNING | 30 |
| ERROR | 40 |
| CRITICAL | 50 |

Именно поэтому при настройке:

```python
level=logging.ERROR
```

в лог записываются только сообщения уровня `ERROR` и `CRITICAL`.

---

# Режим записи файла

По умолчанию используется режим:

```python
filemode="a"
```

`append` — новые записи добавляются в конец файла.

Если нужно очищать файл перед каждым запуском:

```python
logging.basicConfig(
    filename="example.log",
    filemode="w"
)
```

`write` — файл полностью перезаписывается.

---

# Логирование в консоль

Для простого вывода логов в консоль достаточно:

```python
logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s - %(levelname)s - %(message)s"
)
```

Сообщения будут отображаться в терминале.

---

# StreamHandler

```python
console_handler = logging.StreamHandler()
console_handler.setLevel(logging.DEBUG)

logging.getLogger().addHandler(console_handler)
```

`StreamHandler` — обработчик (Handler), который отвечает за вывод логов в поток, обычно в консоль.

---

# getLogger()

```python
logger = logging.getLogger()
```

Возвращает объект класса `Logger`.

Именно `Logger` управляет всеми сообщениями логирования.

У одного логгера может быть несколько обработчиков.

Например:

```
Logger
│
├── Console (StreamHandler)
└── File (FileHandler)
```

В этом случае одно сообщение одновременно попадёт и в консоль, и в файл.

---

# Handler

Handler — это объект, который определяет, **куда будут отправляться логи**.

Наиболее распространённые обработчики:

- `StreamHandler` — вывод в консоль;
- `FileHandler` — запись в файл.

---

# Важные замечания

- `logging` — встроенный модуль Python.
- `basicConfig()` обычно вызывается только один раз.
- Для реальных проектов предпочтительнее использовать `logging`, а не `print()`.
- По умолчанию файл логов открывается в режиме `append`.
- Один `Logger` может использовать несколько `Handler`.

---

# Пример использования в QA Automation

Вместо:

```python
print("Пользователь успешно вошёл")
```

лучше использовать:

```python
logging.info("Пользователь успешно вошёл")
```

Так сообщение можно сохранить в логах и позже проанализировать выполнение автотестов.

---

# Основные выводы

- Логирование позволяет отслеживать работу программы.
- `basicConfig()` используется для первоначальной настройки логирования.
- Уровни логирования помогают фильтровать сообщения по важности.
- Логи можно записывать как в файл, так и выводить в консоль.
- `Logger` управляет процессом логирования.
- `Handler` определяет место вывода логов.
- В проектах по автоматизации логирование используется практически всегда вместо `print()`.
