# Знакомство с Unittest

## Введение

В этом уроке мы познакомимся с тестовым фреймворком `unittest`.

Мы узнаем:

- как работает `unittest`;
- как создать первый автоматизированный тест;
- как запустить тест;
- как интерпретировать результат его выполнения.

---

## Обзор Unittest

Для Python существует множество тестовых фреймворков. Одним из них является `unittest`, встроенный в стандартную библиотеку Python.

Поэтому для его использования не нужно устанавливать дополнительные библиотеки.

`unittest` позволяет:

- автоматизировать выполнение тестов;
- повторно использовать код настройки и очистки тестового окружения;
- группировать тесты по проверяемой функциональности;
- делать тесты независимыми от фреймворка формирования отчётов.

---

## Создание первого теста

Для начала создадим новый файл:

`test_file.py`

Добавим в него следующий код:

```python
# Импортируем unittest
import unittest


# Создаём тестовый класс для реализации и группировки тестов
class TestClass(unittest.TestCase):

    def test_true_method(self):
        # Создаём первый тест
        self.assertTrue(True)
```

Разберём этот код подробнее.

### Импорт unittest

```python
import unittest
```

Импортируем встроенный тестовый фреймворк `unittest`.

### Создание тестового класса

```python
class TestClass(unittest.TestCase):
```

Создаём тестовый класс `TestClass`, который наследуется от `unittest.TestCase`.

Наследование от `unittest.TestCase` предоставляет классу:

- методы для выполнения проверок;
- возможность группировать тесты;
- методы настройки и очистки тестового окружения;
- поддержку запуска тестов через `unittest`.

### Создание тестового метода

```python
def test_true_method(self):
```

Внутри тестового класса создаём тестовый метод `test_true_method`.

Название тестового метода должно начинаться с префикса `test_`. Благодаря этому `unittest` сможет автоматически распознать его как тест.

### Выполнение проверки

```python
self.assertTrue(True)
```

Метод `assertTrue()` проверяет, что переданное ему выражение имеет истинное значение.

В данном случае в него передаётся `True`, поэтому проверка проходит успешно.

## Запуск теста

После создания файла необходимо открыть терминал и убедиться, что мы находимся в той же директории, в которой расположен `test_file.py`.

Для запуска теста используется команда:

```bash
python -m unittest test_file
```

Здесь:

- `python` запускает интерпретатор Python;
- `-m` запускает библиотечный модуль;
- `unittest` — запускаемый тестовый фреймворк;
- `test_file` — название тестового модуля без расширения `.py`.

При успешном выполнении появится примерно следующий результат:

```text
.
----------------------------------------------------------------------
Ran 1 test in 0.000s

OK
```

Точка `.` означает, что один тест прошёл успешно.

Сообщение `Ran 1 test` показывает количество выполненных тестов.

Статус `OK` означает, что все запущенные тесты завершились успешно.

## Пример упавшего теста

Теперь заменим:

```python
self.assertTrue(True)
```

на:

```python
self.assertTrue(False)
```

После этого сохраним файл и снова запустим тест:

```bash
python -m unittest test_file
```

В результате тест завершится с ошибкой:

```text
F
======================================================================
FAIL: test_true_method (test_file.TestClass)
----------------------------------------------------------------------
```

Буква `F` означает `Failure` — тест не прошёл проверку.

Причина падения заключается в том, что метод `assertTrue()` ожидал истинное значение, но получил `False`.

## Основные понятия Unittest

Для работы с `unittest` необходимо понимать четыре основных понятия:

1. Test Fixture.
2. Test Case.
3. Test Suite.
4. Test Runner.

### Test Fixture — тестовая фикстура

**Test Fixture** — блок кода, реализующий действия, которые должны выполняться до или после тестов.

Фикстура используется для подготовки тестового окружения и его очистки после выполнения теста.

Например:

- создание тестового пользователя;
- подключение к базе данных;
- запуск браузера;
- подготовка тестовых данных;
- удаление созданных данных;
- закрытие браузера;
- отключение от базы данных.

### Test Case — тестовый случай

**Test Case** — отдельная тестовая единица, содержащая проверки определённой функциональности.

В `unittest` тестовые случаи реализуются в виде методов тестового класса.

Например:

```python
def test_true_method(self):
    self.assertTrue(True)
```

### Test Suite — набор тестов

**Test Suite** — набор тестов или других тестовых наборов, связанных общим объектом тестирования.

Test Suite позволяет объединить несколько тестов и запустить их вместе.

Например, в один набор можно объединить:

- тесты авторизации;
- тесты регистрации;
- тесты профиля пользователя;
- тесты оформления заказа.

### Test Runner — средство запуска тестов

**Test Runner** — компонент, который:

- управляет выполнением тестов;
- запускает тестовые методы;
- собирает результаты;
- показывает результаты пользователю в понятном формате.

## Требования при использовании Unittest

При работе с `unittest` необходимо соблюдать определённые требования.

### Тесты должны быть методами тестового класса

Тесты должны быть реализованы в виде методов класса, наследующегося от `unittest.TestCase`.

```python
class TestClass(unittest.TestCase):

    def test_example(self):
        self.assertTrue(True)
```

### Использование проверок Unittest

В `unittest` обычно используются собственные методы проверок, доступные через `unittest.TestCase`.

Например:

- `assertTrue()`;
- `assertFalse()`;
- `assertEqual()`;
- `assertNotEqual()`;
- `assertIsNone()`;
- `assertIsNotNone()`.

Пример:

```python
class TestClass(unittest.TestCase):

    def test_sum(self):
        actual_result = 2 + 3
        expected_result = 5

        self.assertEqual(actual_result, expected_result)
```

`unittest` предоставляет набор собственных методов проверок для сравнения фактического и ожидаемого результатов.

Подробнее эти проверки будут рассмотрены в следующем уроке.

## Правила именования

При разработке тестов необходимо придерживаться правил именования, используемых `unittest`.

### Название тестового файла

Название модуля, содержащего тесты, должно начинаться с `test_`.

Примеры:

- `test_file.py`;
- `test_login.py`;
- `test_registration.py`;
- `test_user_profile.py`.

### Название тестового метода

Название тестового метода внутри класса также должно начинаться с `test_`.

Примеры:

```python
def test_login(self):
    pass
```

```python
def test_registration(self):
    pass
```

```python
def test_user_profile_update(self):
    pass
```

Префикс `test_` позволяет тестовому фреймворку автоматически обнаруживать тестовые файлы и методы.

## Полный пример

```python
import unittest


class TestCalculator(unittest.TestCase):

    def test_addition(self):
        actual_result = 2 + 3
        expected_result = 5

        self.assertEqual(actual_result, expected_result)

    def test_true_value(self):
        self.assertTrue(True)


if __name__ == "__main__":
    unittest.main()
```

Конструкция:

```python
if __name__ == "__main__":
    unittest.main()
```

позволяет запускать тесты непосредственно через файл:

```bash
python test_file.py
```

Также тесты можно запустить через модуль `unittest`:

```bash
python -m unittest test_file
```

## Итоги урока

`unittest` — один из стандартных фреймворков для тестирования в Python.

Он встроен в стандартную библиотеку и основан на следующих ключевых понятиях:

- **Test Fixture** — подготовка и очистка тестового окружения;
- **Test Case** — отдельный тест;
- **Test Suite** — набор тестов;
- **Test Runner** — компонент для запуска тестов и отображения результатов.

Основные правила:

- тестовые классы должны наследоваться от `unittest.TestCase`;
- тесты должны быть реализованы как методы тестового класса;
- названия тестовых файлов должны начинаться с `test_`;
- названия тестовых методов должны начинаться с `test_`;
- для проверок используются методы `assert`, предоставляемые классом `unittest.TestCase`.

`unittest` широко используется инженерами по автоматизации тестирования и позволяет создавать структурированные, повторно используемые и удобные для запуска автоматизированные тесты.
