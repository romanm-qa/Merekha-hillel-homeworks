## L2: Unittest Features — Вопросы для собеседования

### Базовый уровень

**1. Что такое Test Case в unittest?**
Класс, унаследованный от `unittest.TestCase`, который группирует связанные проверки. Каждый метод, начинающийся с `test_`, распознаётся как отдельный тест.

**2. Почему файлы с тестами должны начинаться с `test_`?**
Потому что unittest использует автоматическое обнаружение тестов (test discovery), и по умолчанию ищет тесты только в модулях с таким префиксом.

**3. В чём разница между `assertEqual` и обычным `assert a == b`?**
`assertEqual` — специальный метод unittest, который даёт более информативное сообщение об ошибке (показывает оба значения), поддерживает кастомный текст ошибки и интегрирован с отчётами unittest. Обычный `assert` просто вызовет `AssertionError` без такой детализации.

**4. Чем отличается `assertIs` от `assertEqual`?**
`assertEqual` проверяет равенство значений (`==`), а `assertIs` проверяет, что это один и тот же объект в памяти (`is`).

### Средний уровень

**5. В чём разница между `setUp()` и `setUpClass()`?**
`setUp()` выполняется перед **каждым** тестом в классе, `setUpClass()` — **один раз** перед всеми тестами класса. `setUpClass` — метод класса (`@classmethod`), а `setUp` — обычный метод экземпляра.

**6. Выполнится ли `tearDown()`, если тест упал с ошибкой?**
Да, `tearDown()` выполнится в любом случае — даже если тест зафейлился или выбросил исключение. Главное условие — чтобы перед этим успешно отработал `setUp()`.

**7. Что будет, если `setUp()` упадёт с ошибкой?**
Тест будет помечен как ошибочный (error), сам тест не выполнится, и `tearDown()` тоже не будет вызван.

**8. Зачем нужен Test Suite, если тесты и так объединены в Test Case?**
Test Suite позволяет гибко группировать тесты для запуска — например, собрать в один набор тесты из разных классов или файлов, объединить несколько Suite в один более крупный набор (например, "smoke suite" из нескольких тест-кейсов разных модулей).

**9. Как правильно собрать TestSuite в актуальной версии Python?**
Через `unittest.TestLoader`:
```python
loader = unittest.TestLoader()
suite = loader.loadTestsFromTestCase(TestCaseClass)
```
`unittest.makeSuite()` — устаревший (deprecated с 3.9, удалён в 3.13) способ, но его можно встретить в легаси-коде.

**10. Как пропустить тест только при определённом условии?**
Через `@unittest.skipIf(condition, reason)` — пропустить, если условие `True`, или `@unittest.skipUnless(condition, reason)` — пропустить, если условие `False`.

### Продвинутый уровень / на подумать

**11. Зачем нужен `@unittest.expectedFailure`, если можно просто написать тест без него?**
Если тест без этого декоратора упадёт — это будет учтено как обычный провал (Failed), и тестовый прогон будет считаться "нездоровым". `expectedFailure` явно документирует, что падение теста — **ожидаемое и корректное поведение** (например, известный баг или ограничение функциональности), и статус прогона остаётся чистым (Passed), пока тест продолжает падать как ожидается.

**12. Чем отличается ошибка (Error) от провала теста (Failure) в unittest?**
- **Failure** — это когда сработал `assert` и условие проверки не выполнилось (ожидаемое поведение теста — обнаружить баг).
- **Error** — это когда во время выполнения теста возникло непредвиденное исключение (например, `TypeError`, `KeyError`), не связанное напрямую с assert-проверкой — то есть сам тест "сломался", а не обнаружил баг в приложении.

**13. Как ты объяснишь разницу между Test Case и Test Suite простыми словами, если тебя спросят на collections-аналогии?**
Test Case — это как отдельный список тестов (класс с методами `test_...`). Test Suite — это как коллекция, в которую можно сложить несколько Test Case (и даже другие Suite), чтобы запустить их вместе как один набор.

**14. Если у тебя есть fixtures в двух разных уровнях (setUpClass и setUp), в каком порядке они выполнятся для трёх тестов в одном классе?**
setUpClass()          ← один раз, перед всеми тестами

setUp()   → test_1 → tearDown()
setUp()   → test_2 → tearDown()
setUp()   → test_3 → tearDown()

tearDownClass()        ← один раз, после всех тестов
