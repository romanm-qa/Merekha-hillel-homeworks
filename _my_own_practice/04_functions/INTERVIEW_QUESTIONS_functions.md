# Вопросы к собеседованию: функции в Python

Сначала отвечай самостоятельно, затем сверяйся с ответом. Задания на вывод разбирай без запуска. Для мини-собеседования проходи по одному вопросу за раз.

## Основы

### 1. Что такое функция и зачем она нужна?

Объект, который можно вызвать для выполнения задачи. Функции помогают повторно использовать код, разделять программу на понятные части и проверять вычисления отдельно.

### 2. Когда выполняется тело функции, определённой через def?

При вызове. Само выполнение `def` создаёт объект функции и связывает его с именем. Значения по умолчанию при этом вычисляются сразу.

### 3. Чем function отличается от function()?

`function` — ссылка на объект функции; `function()` — её вызов. Результат вызова может быть любым объектом, в том числе другой функцией.

### 4. Чем параметр отличается от аргумента?

Параметр — имя в определении функции. Аргумент — значение, переданное при вызове.

```python
def greet(name):  # name — параметр.
    return f"Hello, {name}!"

greet("Roman")  # "Roman" — аргумент.
```

### 5. Должна ли внешняя переменная называться так же, как параметр?

Нет. `greet(user_name)` передаёт значение выражения `user_name` параметру `name`.

### 6. Чем return отличается от print?

`return` завершает вызов и возвращает значение вызывающему коду. `print()` выводит информацию и сам возвращает `None`. Напечатанный результат автоматически не становится возвращённым.

### 7. Что возвращает функция без return? А return без значения?

В обоих случаях — `None`, если выполнение нормально дошло до конца или до такого `return`.

### 8. Можно ли использовать несколько return?

Да, например в разных ветках условия. Выполненный `return` завершает текущий вызов. При наличии `finally` он выполняется перед выходом.

### 9. Может ли функция вернуть несколько значений?

Она возвращает один объект. В записи `return first, second` этим объектом является кортеж, который можно распаковать.

### 10. Что такое docstring?

Строка документации в начале тела функции. Доступна через `function.__doc__`. Имя функции доступно через `function.__name__`.

### 11. Для чего нужен pass?

Это инструкция, которая ничего не делает. Подходит для временной заглушки тела. Функция с одним `pass` возвращает `None`.

## Параметры и аргументы

### 12. Как передаются позиционные и именованные аргументы?

Позиционные связываются с параметрами по порядку, именованные — по имени. В обычном вызове позиционные аргументы располагаются перед именованными.

### 13. Можно ли менять порядок именованных аргументов?

Да. Например, `subtract(minuend=10, subtrahend=3)` и `subtract(subtrahend=3, minuend=10)` передают одинаковые значения.

### 14. Что будет, если заполнить один параметр дважды?

Возникнет `TypeError`.

```python
def add(first, second):
    return first + second

# add(1, first=2, second=3)
```

### 15. Какие ошибки вызова обычно приводят к TypeError?

Пропущенный обязательный аргумент, лишний аргумент, неизвестное имя, повторное заполнение параметра или нарушение ограничений передачи, заданных `/` и `*`.

### 16. Когда используется значение по умолчанию?

Когда соответствующий аргумент не передан. Явно переданные `0`, `False`, `None` и пустая строка автоматически им не заменяются.

### 17. Что означает / в определении функции?

Параметры перед `/` принимаются только позиционно. Например, `def divide(first, second, /)` не допускает передачу этих параметров по имени.

### 18. Что означает отдельная * в определении?

Параметры после неё передаются только по имени. То же правило действует для параметров, следующих после `*args`.

### 19. Может ли параметр только по имени быть обязательным?

Да, если у него нет значения по умолчанию.

```python
def format_price(amount, *, currency):
    return f"{amount:.2f} {currency}"
```

### 20. Допустимо ли def profile(*, role='student', name)?

Да. Параметры только по имени не требуют размещать все обязательные параметры перед необязательными.

### 21. Как передать параметры этой функции?

```python
def calculate(amount, /, discount=0, *, currency="UAH"):
    return amount, discount, currency
```

`amount` — только позиционно; `discount` — позиционно или по имени; `currency` — только по имени. Корректный вызов: `calculate(100, discount=10, currency="USD")`.

## Упаковка и распаковка

### 22. Что делают *args и **kwargs в определении функции?

Собирают дополнительные позиционные аргументы в кортеж и дополнительные именованные — в словарь. Обычные параметры сначала получают соответствующие значения.

### 23. Обязательны ли имена args и kwargs?

Нет. Это соглашение. Поведение задают звёздочки: `*values` и `**options` работают так же.

### 24. Что получат args и kwargs при вызове без аргументов?

Пустой кортеж `()` и пустой словарь `{}`.

### 25. Чем collect(values) отличается от collect(*values)?

Первый вызов передаёт объект одним аргументом. Второй распаковывает его элементы в отдельные позиционные аргументы.

### 26. Что делают * и ** при вызове?

`*` распаковывает итерируемый объект в позиционные аргументы. `**` распаковывает отображение, например словарь, в именованные аргументы. Его ключи должны быть строками.

### 27. Что произойдёт при распаковке словаря через одну звёздочку?

Передадутся ключи, а не значения и не пары ключ–значение.

### 28. Можно ли распаковать несколько списков и словарей в одном вызове?

Да. Например, `function(*first, *second, **options)`. Именованные аргументы не должны повторяться; итоговые аргументы должны соответствовать параметрам функции.

### 29. Делают ли *args и **kwargs функцию безопаснее?

Нет. Они расширяют принимаемые аргументы, но не проверяют их смысл и типы. Для известных входных данных явные параметры обычно понятнее.

## Объекты и значения по умолчанию

### 30. Как передаются объекты в функцию?

Параметры связываются с переданными объектами. Автоматического копирования нет. Одно правило применяется к изменяемым и неизменяемым объектам.

### 31. Чем изменение объекта отличается от переприсваивания параметра?

`items.append(1)` изменяет сам список, и это видно другим ссылкам на него. `items = [1]` связывает локальный параметр с другим объектом и не переназначает внешнюю переменную.

### 32. Чем += отличается от + для списка?

`items += [1]` расширяет существующий список. `items = items + [1]` создаёт новый список и переприсваивает имя. Поведение `+=` зависит от типа объекта: для чисел это не изменение числа на месте.

### 33. Нужен ли return, чтобы изменение переданного списка было видно снаружи?

Нет. Изменение общего объекта видно независимо от возвращаемого значения функции.

### 34. Что такое поверхностная копия?

Новый внешний контейнер со ссылками на те же вложенные объекты. Например, изменение вложенного списка через копию может быть видно в исходной структуре.

### 35. Можно ли изменить список внутри кортежа?

Да. Кортеж не позволяет заменить свои элементы, но изменяемый объект, на который ссылается элемент, можно менять.

### 36. Когда вычисляются значения параметров по умолчанию?

При выполнении определения функции. Они не вычисляются заново для каждого вызова.

### 37. Почему items=[] в параметрах может быть ошибкой?

Один список по умолчанию повторно используется вызовами, в которых этот аргумент пропущен. Изменения накапливаются.

### 38. Как создать отдельный список для каждого вызова без аргумента?

Использовать `items=None`, а внутри — `if items is None: items = []`.

### 39. Почему проверяем is None, а не if not items?

Пустой список тоже ложен, но может быть явно передан пользователем. `if not items` заменит его новым списком, что может нарушить ожидаемое поведение.

## Области видимости

### 40. Чем пространство имён отличается от области видимости?

Пространство имён связывает имена с объектами. Область видимости определяет, откуда доступны имена.

### 41. Что означает LEGB?

Обычный поиск имён внутри функций: Local → Enclosing → Global → Built-in. Внешние функции проверяются от ближайшей к более дальней.

### 42. Что вызывает UnboundLocalError?

Чтение локального имени до того, как ему присвоено значение. Если внутри функции имя считается локальным, Python не использует одноимённую глобальную переменную как запасной вариант.

### 43. Чем отличаются global и nonlocal?

`global` направляет привязку имени в область модуля. `nonlocal` — к существующей привязке в ближайшей подходящей области внешней функции. Глобальная область для `nonlocal` не подходит.

### 44. Нужен ли global для чтения внешней переменной или append() к глобальному списку?

Обычно нет. Он нужен для переприсваивания глобального имени, а не для чтения или изменения самого объекта через метод.

### 45. Создают ли if и обычный for отдельную область видимости?

Нет. Имена, присвоенные в выполненном блоке, остаются в текущей области. Если присваивание не выполнялось, новое значение не появится.

### 46. Для чего нужны globals() и locals()?

Для доступа к глобальному словарю имён и просмотра текущих локальных имён. В учебных примерах `locals()` используем для просмотра, а не как способ изменения локальных переменных.

## Функции как объекты и lambda

### 47. Что означает «функции — объекты первого класса»?

Их можно сохранять в переменных и коллекциях, передавать как аргументы и возвращать из других функций.

### 48. Копируется ли функция при operation = square?

Нет. Оба имени связаны с одним объектом функции: `operation is square` возвращает `True`.

### 49. Что такое lambda?

Выражение, создающее функцию с телом из одного выражения. Результат тела автоматически возвращается. Для сложной или именованной повторно используемой логики обычно понятнее `def`.

### 50. Что принимает key при сортировке?

Функцию, вычисляющую ключ для каждого элемента. Например, `key=len` сортирует по длине, а `key=lambda student: student[1]` — по второму полю. Сам элемент в результате не заменяется ключом.

### 51. Чем отличаются sorted() и list.sort()?

`sorted()` возвращает новый список из итерируемого объекта. `list.sort()` изменяет существующий список и возвращает `None`. Оба способа поддерживают стабильную сортировку.

### 52. Чем отличаются map(), filter() и reduce()?

`map()` преобразует элементы; `filter()` отбирает элементы; `reduce()` накапливает результат через функцию двух аргументов. Первые два возвращают итераторы. `reduce()` импортируется из `functools`.

### 53. Что делает filter(None, values)?

Оставляет истинные элементы. Например, `[0]` остаётся: это непустой список.

### 54. Можно ли повторно получить все элементы из исчерпанного map или filter?

Нет. Нужно создать новый итератор или заранее сохранить полученные элементы в коллекцию.

### 55. Как reduce() работает с пустым объектом?

С начальным значением возвращает его. Без начального значения вызывает `TypeError`.

### 56. Чем отличаются bool([]), all([]) и any([])?

`bool([])` — `False`, поскольку список пуст. `all([])` — `True`, поскольку нет ложных элементов. `any([])` — `False`, поскольку нет истинных элементов.

### 57. Проверяют ли all() и any() каждый элемент обязательно?

Нет. `all()` заканчивает на первом ложном, `any()` — на первом истинном. Переданный итератор может быть использован только частично.

## Рекурсия и замыкания

### 58. Что необходимо для завершения рекурсии?

Базовый случай и логика, приближающая выполнение к нему для допустимых входных данных. Одного наличия условия остановки недостаточно.

### 59. Почему код после рекурсивного вызова выполняется в обратном порядке?

Каждый вызов ждёт завершения вложенного, затем продолжает работу. Сначала завершается самый глубокий вызов.

### 60. Может ли правильная рекурсия вызвать RecursionError?

Да. Если глубина вложенных вызовов превышает допустимый предел до достижения базового случая.

### 61. Почему наивная рекурсия Фибоначчи медленная?

Она многократно вычисляет одни и те же значения. Цикл избегает этих повторов. Другой подход — сохранять рассчитанные результаты, то есть использовать мемоизацию.

### 62. Что такое замыкание?

Функция, сохраняющая доступ к переменным внешней функции. Этот доступ может сохраняться после завершения внешнего вызова.

### 63. Обязательно ли возвращать внутреннюю функцию для замыкания?

Нет. Возврат — распространённый способ сохранить её, но можно, например, добавить функцию в коллекцию.

### 64. Для чего nonlocal в счётчике-замыкании?

Чтобы `count += 1` переприсваивало переменную внешней функции. Для изменения внешнего списка через `append()` `nonlocal` не требуется.

### 65. Всегда ли замыкания имеют независимое состояние?

Нет. Отдельные вызовы фабрики могут создавать отдельные переменные, а несколько функций из одного вызова могут разделять одну переменную.

### 66. Что такое позднее связывание в замыканиях?

Функция обращается к актуальному значению внешней переменной при вызове. Функции из цикла могут разделять одну переменную и после завершения цикла видеть её последнее значение.

### 67. Как сохранить отдельное значение для каждой функции из цикла?

Создавать функцию отдельным вызовом фабрики или сохранять текущее значение в параметре по умолчанию. Второй способ использует значения по умолчанию, а не замыкание для хранения этого значения.

## Декораторы и проектирование

### 68. Что такое декоратор функции?

Вызываемый объект, который получает функцию и возвращает объект для связи с её именем. В типичных учебных примерах возвращается обёртка с дополнительным поведением.

### 69. Чему соответствует @decorator?

Применению `function = decorator(function)` после определения функции. Декоратор применяется при выполнении определения, а обёртка — при последующем вызове.

### 70. Зачем wrapper принимает *args и **kwargs?

Чтобы получить аргументы вызова и передать их исходной функции через `function(*args, **kwargs)`. Ограничения исходной функции при этом сохраняются.

### 71. Почему декорированная функция может начать возвращать None?

Обёртка могла вызвать исходную функцию, но не вернуть её результат.

### 72. Для чего functools.wraps?

Копирует основные метаданные исходной функции на обёртку и добавляет `__wrapped__`. Сам объект остаётся обёрткой. Это не механизм передачи аргументов и не сохранение результата вызова.

### 73. В каком порядке применяются несколько декораторов?

Снизу вверх: `@first` над `@second` соответствует `function = first(second(function))`. При вызове первой начинает работу внешняя обёртка.

### 74. Как устроен декоратор с параметрами?

Фабрика получает настройки, возвращённый декоратор получает исходную функцию, а обёртка получает аргументы будущих вызовов. Например, `@repeat(3)` соответствует `function = repeat(3)(function)`.

### 75. Выполнится ли код после function(), если та выбросит исключение?

Обычный код после вызова — нет. Для завершающего действия и при успехе, и при исключении используется `finally`. Он сам по себе не подавляет исключение.

### 76. Как измерить длительность вызова?

Взять разность значений `perf_counter()` до и после операции. Если нужен вывод времени при ошибке, завершение измерения можно поместить в `finally`.

### 77. Какие признаки у понятной функции?

Ясное имя и задача, понятные параметры и результат, минимум неожиданных изменений внешнего состояния. Точного ограничения на количество строк нет.

### 78. Зачем отделять вычисления от input() и print()?

Чтобы использовать вычисление с разными источниками данных и проще проверять результат. Ввод и вывод можно оставить вызывающему коду.

## Что выведет код?

### 79. print вместо return

```python
def add(first, second):
    print(first + second)

result = add(2, 3)
print(result)
```

Ответ:

```text
5
None
```

### 80. Распаковка результата

```python
def get_pair():
    return 10, 20

result = get_pair()
first, second = result
print(type(result).__name__)
print(first, second)
```

Ответ:

```text
tuple
10 20
```

### 81. Сбор аргументов

```python
def collect(first, *args, **kwargs):
    return first, args, kwargs

print(collect(1, 2, 3, name="Roman"))
```

Ответ:

```text
(1, (2, 3), {'name': 'Roman'})
```

### 82. Изменение объекта и переприсваивание

```python
def change(items):
    items.append(3)
    items = [99]
    return items

numbers = [1, 2]
result = change(numbers)
print(numbers)
print(result)
```

Ответ:

```text
[1, 2, 3]
[99]
```

### 83. Общий список по умолчанию

```python
def collect(value, items=[]):
    items.append(value)
    return items

print(collect(1))
print(collect(2))
```

Ответ:

```text
[1]
[1, 2]
```

### 84. Момент вычисления значения по умолчанию

```python
language = "Python"

def read(value=language):
    return value

language = "Java"
print(read())
print(read(language))
```

Ответ:

```text
Python
Java
```

### 85. Локальная переменная

```python
counter = 10

def increase():
    counter += 1
    return counter

increase()
```

Ответ: возникает `UnboundLocalError`. Присваивание делает `counter` локальным именем, а до чтения ему ещё не задано локальное значение.

### 86. Поверхностная копия

```python
rows = [[1], [2]]
copied_rows = rows.copy()
copied_rows[0].append(3)
print(rows)
print(copied_rows is rows)
```

Ответ:

```text
[[1, 3], [2]]
```

### 89. Независимые счётчики

### 90. Позднее связывание

## Практика без готовых решений

Пиши функции самостоятельно. Сначала — условие в комментариях и заготовка функции, затем реализация. Во время проверки выводи исходные данные и результат с `!r`.

1. `remove_duplicates(numbers)` — верни новый список без повторов, сохрани порядок. Исходный список не меняй. Для пустого списка верни `[]`.
2. `get_min_max(numbers)` — верни кортеж минимума и максимума непустого списка чисел. Для пустого списка выброси `ValueError`.
3. `calculate_price(amount, /, discount=0, *, currency="UAH")` — верни строку с итоговой ценой до двух знаков и валютой. Для отрицательной цены и скидки вне 0–100 выброси `ValueError`.
4. `sum_numbers(*numbers)` — верни сумму аргументов. Без аргументов верни `0`.
5. `create_profile(name, **details)` — верни новый словарь с именем и дополнительными полями.
6. `add_item(item, items=None)` — добавь элемент в переданный список и верни его. Без списка создавай новый при каждом вызове. Проверь явно переданный пустой список.
7. `apply_to_numbers(function, numbers)` — верни список результатов применения переданной функции к числам.
8. Отсортируй список пар «имя, балл» по баллу через lambda, сохранив исходный список.
9. `factorial(number)` — рекурсивно вычисли факториал целого неотрицательного числа. Отрицательный аргумент отклони через `ValueError`.
10. `flatten_list(items)` — преврати список с произвольной глубиной вложенных списков в плоский. Исходные данные не меняй. Считай, что циклических ссылок нет.
