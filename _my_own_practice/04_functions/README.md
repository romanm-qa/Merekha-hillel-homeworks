## 1. Определение и вызов функции

`def` создаёт функцию и связывает её с именем. Тело выполняется при вызове, а не при определении. При каждом вызове функция выполняет своё тело заново.

```python
def greet(name):
    return f"Hello, {name}!"

user_name = "Roman"
print(f"Исходное имя: {user_name!r}")
print(f"greet(user_name) -> {greet(user_name)!r}")
```

- `name` — параметр в определении.
- `user_name` — выражение, значение которого передаётся как аргумент.
- `greet` — сама функция.
- `greet(user_name)` — вызов функции.

Переменная снаружи не обязана называться так же, как параметр.

### return и print

| Конструкция | Назначение |
| --- | --- |
| `print(value)` | Выводит значение; сам вызов print возвращает None |
| `return value` | Завершает текущий вызов функции и возвращает значение |
| `return` | Завершает текущий вызов и возвращает None |
| Конец функции без return | Возвращает None |

Результат через `return` можно сохранить, передать дальше или использовать в вычислении. Функция, которая только печатает результат, автоматически не возвращает напечатанное значение.

```python
def add(first, second):
    return first + second

result = add(10, 5)
print(f"Результат: {result!r}")
```

После выполненного `return` обычное выполнение тела прекращается. Если есть блок `finally`, он выполняется перед выходом.

`return minimum, maximum` возвращает один объект — кортеж. Его можно распаковать:

```python
def get_min_max(numbers):
    return min(numbers), max(numbers)

numbers = [4, 8, 2, 6]
minimum, maximum = get_min_max(numbers)
```

Здесь ожидается непустая коллекция чисел: `min()` и `max()` без default не принимают пустой объект.

### Документация и заглушка

Docstring — строка документации в начале тела функции. Она доступна через `function.__doc__`; имя — через `function.__name__`.

`pass` ничего не делает и подходит для временной заглушки. Функция с одним `pass` возвращает `None`.

## 2. Параметры и аргументы

Позиционный аргумент связывается с параметром по порядку, именованный — по имени.

```python
def subtract(minuend, subtrahend):
    return minuend - subtrahend

subtract(10, 3)
subtract(minuend=10, subtrahend=3)
subtract(subtrahend=3, minuend=10)
subtract(10, subtrahend=3)
```

Все четыре вызова возвращают `7`.

В обычном вызове позиционные аргументы идут перед именованными. Один параметр нельзя заполнить дважды. Отсутствующий обязательный аргумент, лишний аргумент или неизвестное имя вызывают `TypeError`, если сигнатура функции их не допускает.

### Значения по умолчанию

```python
def power(number, exponent=2):
    return number ** exponent
```

`power(5)` возвращает `25`, `power(5, 3)` — `125`. Явно переданный `0` не заменяется значением по умолчанию: `power(5, 0)` возвращает `1`.

### Ограничения / и *

```python
def calculate_price(amount, /, discount=0, *, currency="UAH"):
    final_amount = amount * (1 - discount / 100)
    return f"{final_amount:.2f} {currency}"
```

| Параметр | Допустимая передача |
| --- | --- |
| `amount`, перед / | Только позиционно |
| `discount`, между / и * | Позиционно или по имени |
| `currency`, после * | Только по имени |

`/` и отдельная `*` — разделители, а не параметры. Параметры после `*args` тоже передаются только по имени.

Обязательность и способ передачи — разные характеристики. Параметр только по имени может быть обязательным:

```python
def create_profile(*, role="student", name):
    return f"{name}: {role}"
```

Среди обычных позиционных или позиционно-именованных параметров параметр без значения по умолчанию не ставят после параметра со значением по умолчанию. Для параметров только по имени такого ограничения нет.

## 3. Упаковка и распаковка

| Место | Одна звёздочка | Две звёздочки |
| --- | --- | --- |
| Определение функции | *args собирает дополнительные позиционные аргументы в кортеж | **kwargs собирает дополнительные именованные аргументы в словарь |
| Вызов функции | *values распаковывает итерируемый объект в позиционные аргументы | **data распаковывает отображение в именованные аргументы |

`args` и `kwargs` — обычные, общепринятые имена. Поведение задают звёздочки.

```python
def collect_arguments(*args, **kwargs):
    return args, kwargs

print(f"{collect_arguments(10, 20, name='Roman')!r}")
# ((10, 20), {'name': 'Roman'})
```

Обычные параметры получают свои значения, а в `args` и `kwargs` попадают оставшиеся аргументы.

```python
def add(first, second):
    return first + second

numbers = [10, 20]
data = {"first": 10, "second": 20}

add(*numbers)
add(**data)
```

Без звёздочки список передаётся одним объектом. `*data` у словаря передаёт ключи, `**data` — именованные аргументы с соответствующими значениями.

Для `**` нужны строковые ключи. Имена не должны повторяться между распаковками и явными именованными аргументами в одном вызове. После распаковки действуют обычные ограничения параметров функции.

`*args` и `**kwargs` полезны для переменного числа аргументов и функций-посредников. Они не делают функцию автоматически безопаснее. Если входные данные известны, явные параметры обычно понятнее.

## 4. Переданные объекты и значения по умолчанию

При вызове параметр связывается с переданным объектом. Автоматическая копия не создаётся. Это правило одинаково для изменяемых и неизменяемых объектов.

| Действие внутри функции | Что видно снаружи |
| --- | --- |
| `numbers.append(30)` | Переданный список изменился |
| `numbers = [100, 200]` | Внешняя переменная осталась связана с прежним списком |
| `numbers += [30]` для списка | Исходный список расширился |
| `numbers = numbers + [30]` для списка | Создан новый список; исходный не изменился |

Неизменяемый объект нельзя изменить на месте. Присваивание параметру другого числа или строки не переназначает внешнюю переменную.

`list.copy()` создаёт поверхностную копию: внешние списки разные, а вложенные объекты остаются общими. Кортеж тоже может содержать изменяемый список: неизменяемость кортежа не запрещает менять этот список.

### Ловушка изменяемого значения по умолчанию

Значения по умолчанию вычисляются при выполнении `def`, а не при каждом вызове.

```python
def add_item_shared(item, items=[]):
    items.append(item)
    return items

print(add_item_shared(1))  # [1]
print(add_item_shared(2))  # [1, 2]
```

Если нужен новый список для каждого вызова без аргумента:

```python
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Проверяем `is None`, а не `if not items`: явно переданный пустой список нужно сохранить. Переданный список эта функция изменит — новый создаётся только при `items is None`.

Момент вычисления значений по умолчанию важен и для чисел или строк: последующее переприсваивание внешней переменной не меняет уже сохранённое значение по умолчанию.

## 5. Пространства имён и области видимости

Пространство имён связывает имена с объектами. Область видимости определяет доступность имён.

Для обычного поиска имён внутри функций используется порядок LEGB:

| Уровень | Где ищется имя |
| --- | --- |
| Local | Текущая функция |
| Enclosing | Внешние функции, от ближайшей к более дальней |
| Global | Модуль, в котором определена функция |
| Built-in | Встроенные объекты Python |

Параметры и обычные присваивания внутри функции создают локальные имена. Если имя считается локальным, чтение до присваивания вызывает `UnboundLocalError`: поиск не переключается на одноимённую глобальную переменную. Не найденное имя обычно вызывает `NameError`.

| Конструкция | Назначение |
| --- | --- |
| `global name` | Переприсваивание имени в области модуля |
| `nonlocal name` | Переприсваивание существующего имени в ближайшей подходящей области внешней функции |
| `globals()` | Словарь глобального пространства имён |
| `locals()` | Просмотр текущих локальных имён |

Для чтения внешнего имени эти объявления обычно не нужны. Для изменения внешнего списка через `append()` они тоже не нужны: само имя не переприсваивается.

Обычные `if`, `for` и `while` не создают отдельную область видимости. Если присваивание в блоке произошло, имя остаётся в текущей области. Это не означает, что внутри функции можно прочитать локальное имя до присваивания.

Не называй переменные `list`, `len`, `sum` или `print`: так можно перекрыть встроенные имена. `locals()` в примерах используем для просмотра, а не как способ присваивания переменных.

## 6. Функции как объекты и lambda

Функцию можно сохранить в переменной, положить в коллекцию, передать другой функции или вернуть из неё.

```python
def square(number):
    return number ** 2

operation = square
print(f"operation is square -> {operation is square!r}")
print(f"operation(5) -> {operation(5)!r}")
```

Присваивание не копирует функцию: создаётся ещё одно имя того же объекта.

`lambda` создаёт функцию из одного выражения. Результат выражения возвращается автоматически.

```python
students = [("Roman", 90), ("Alex", 85), ("Kate", 95)]
sorted_students = sorted(students, key=lambda student: student[1])
```

`key` получает функцию, вычисляющую ключ сортировки. Исходные элементы остаются элементами результата. Если подходит готовая функция, можно передать её напрямую: `sorted(words, key=len)`.

`sorted()` возвращает новый список, `list.sort()` изменяет исходный и возвращает `None`. Сортировка стабильна: элементы с одинаковыми ключами сохраняют взаимный порядок.

| Инструмент | Назначение |
| --- | --- |
| `map(function, iterable)` | Преобразует элементы; возвращает итератор |
| `filter(function, iterable)` | Оставляет элементы с истинным результатом проверки; возвращает итератор |
| `filter(None, iterable)` | Оставляет истинные элементы |
| `reduce(function, iterable, initial)` | Накапливает результат через функцию двух аргументов |
| `all(iterable)` | Проверяет, все ли элементы истинны |
| `any(iterable)` | Проверяет, есть ли истинный элемент |

`reduce()` импортируется из `functools`. Пустой объект без начального значения вызывает `TypeError`, с начальным — возвращает это значение.

Итераторы `map` и `filter` вычисляют элементы по мере обхода и исчерпываются. Повторное `list()` для уже исчерпанного итератора вернёт `[]`.

`all()` останавливается на первом ложном элементе, `any()` — на первом истинном. Для пустого списка:

```python
bool([])  # False: список пуст.
all([])   # True: нет ложных элементов.
any([])   # False: нет истинных элементов.
```

Для простой обработки списка comprehension часто понятнее сочетания `map()` или `filter()` с lambda. Для обычной суммы используй `sum()`, а не `reduce()`.

## 7. Рекурсия

Рекурсия — вызов функции из неё самой; возможна и цепочка вызовов через другие функции. Для завершения нужен базовый случай, к которому приближается выполнение.

```python
def factorial(number):
    if number < 0:
        raise ValueError("Число должно быть неотрицательным")
    if number == 0:
        return 1
    return number * factorial(number - 1)
```

Пример рассчитан на целые неотрицательные аргументы. Проверка `< 0` не заменяет проверку типа.

Каждый вызов имеет свои локальные значения. Сначала вызовы углубляются, затем возвращаются в обратном порядке. Код перед рекурсивным вызовом выполняется при углублении, после него — при возвращении.

Если результат рекурсивного вызова нужен предыдущему уровню, его необходимо вернуть или использовать в возвращаемом выражении. Пропущенный `return` может привести к `None` и ошибкам вычисления.

Python ограничивает глубину рекурсии. `RecursionError` возможен даже при правильном базовом случае, если вложенных вызовов слишком много.

Наивная рекурсия Фибоначчи повторяет вычисления и медленна для больших индексов. В примерах используется нумерация с нуля: `fibonacci(0) = 0`, `fibonacci(1) = 1`.

Рекурсия удобна для вложенных структур и деревьев. Для обычного последовательного повторения цикл часто проще и экономнее. Пример обработки вложенных списков рассчитан на структуры без циклических ссылок.

## 8. Замыкания

Замыкание сохраняет доступ к переменным внешней функции. Доступ может оставаться после завершения внешнего вызова.

```python
def create_multiplier(multiplier):
    def multiply(number):
        return number * multiplier
    return multiply

multiply_by_two = create_multiplier(2)
print(f"multiply_by_two(10) -> {multiply_by_two(10)!r}")
```

Возврат внутренней функции — распространённый, но не обязательный способ сохранить замыкание. Например, его можно добавить в список.

Для чтения внешней переменной `nonlocal` не нужен, для её переприсваивания — нужен. Изменение списка через `append()` не является переприсваиванием имени.

Отдельные вызовы фабрики могут создавать независимое состояние. Несколько функций из одного вызова могут разделять одну переменную.

### Позднее связывание

Замыкание сохраняет доступ к переменной, а не обязательно снимок её значения. Функции, созданные в цикле и использующие одну внешнюю переменную, при последующем вызове увидят её актуальное значение.

Способы сохранить отдельный множитель:

- вызвать фабрику замыканий отдельно на каждой итерации;
- зафиксировать текущее значение в параметре по умолчанию.

Во втором случае сохранение множителя происходит через значение параметра по умолчанию, а не через замыкание.

## 9. Декораторы

Декоратор принимает функцию и возвращает объект, который связывается с её именем. В примерах этим объектом является обёртка с дополнительным поведением.

```python
from functools import wraps


def log_call(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        print(f"Вызов: {function.__name__!r}")
        return function(*args, **kwargs)
    return wrapper


@log_call
def add(first, second):
    return first + second
```

`@log_call` соответствует применению `add = log_call(add)` после определения функции.

Декоратор применяется при выполнении определения, обёртка — при последующем вызове. `*args` и `**kwargs` передают аргументы дальше. `return` сохраняет результат исходного вызова.

`wraps()` копирует основные метаданные исходной функции и добавляет `__wrapped__`. Объект остаётся обёрткой. Вызов через `__wrapped__` обходит соответствующий уровень обёртки.

Код после вызова исходной функции не выполнится, если вызов выбросил исключение. Для завершающего действия независимо от результата используется `try/finally`.

### Несколько декораторов

```python
@first_decorator
@second_decorator
def target():
    pass
```

Применение соответствует `target = first_decorator(second_decorator(target))`. При вызове сначала выполняется внешняя обёртка — `first_decorator`.

### Декоратор с настройками

У фабрики декораторов три уровня:

| Уровень | Что получает |
| --- | --- |
| `repeat(times)` | Настройку декоратора |
| `decorator(function)` | Исходную функцию |
| `wrapper(*args, **kwargs)` | Аргументы будущего вызова |

`@repeat(3)` соответствует `function = repeat(3)(function)`. В учебном примере исходная функция вызывается три раза и возвращается последний результат.

Состояние обёртки можно хранить в замыкании, например для подсчёта вызовов. Для измерения длительности используется `perf_counter()`; время меняется от запуска к запуску.

Эти обёртки демонстрируют обычные синхронные функции. Асинхронные функции и генераторы требуют отдельного рассмотрения.

## Проектирование функций

- Выбирай понятное имя в snake_case: `calculate_total`, `find_user`.
- Объединяй в функции одну понятную задачу. Большую задачу дели на несколько шагов.
- Передавай зависимости через параметры и возвращай результаты явно.
- Отделяй вычисление от ввода и вывода, когда это помогает повторному использованию и проверке.
- Не меняй переданные коллекции неожиданно: такое поведение должно быть понятно из назначения и документации.
- Указывай допустимые входные данные и поведение при ошибках.
- Не делай функцию сложнее только ради lambda, рекурсии или декоратора.

Точного ограничения на количество строк нет. Главное — функция должна оставаться понятной, с ясными входными данными и результатом.

## Частые ошибки

| Ошибка | Что проверить |
| --- | --- |
| Функция не выполняется | Есть ли вызов со скобками |
| Вместо числа получен None | Возвращается ли результат во всех нужных ветках |
| TypeError при вызове | Количество, имена и способы передачи аргументов |
| Исходный список неожиданно изменился | Меняет ли функция переданный объект или вложенный общий объект |
| Список накапливается между вызовами | Нет ли изменяемого значения по умолчанию |
| UnboundLocalError | Не читается ли локальное имя до присваивания |
| Все функции из цикла возвращают одинаковый результат | Не используют ли они одну внешнюю переменную |
| После декорирования пропал результат | Есть ли return в обёртке |
| Имя функции стало wrapper | Используется ли wraps |
| Рекурсия не завершается | Достижим ли базовый случай для переданных данных |

## Запуск и проверка

Запускай каждый файл отдельно из папки с материалами:

```bash
python3 01_functions_basics.py
python3 02_function_arguments.py
python3 03_args_kwargs_and_unpacking.py
python3 04_mutable_arguments_and_defaults.py
python3 05_namespaces_and_scopes.py
python3 06_functions_as_objects_and_lambda.py
python3 07_recursion.py
python3 08_closures.py
python3 09_decorators.py
```

Примеры не требуют пользовательского ввода. Намеренные ошибки либо обработаны через `try/except`, либо закомментированы.

`!r` показывает представление значения: строки видны в кавычках, пустая строка — как `''`. Для исключений выводится название класса и сообщение.

В самостоятельных задачах проверяй обычные значения, граничные случаи и допустимые пустые коллекции. Пустые и отрицательные значения подходят не каждой функции: ориентируйся на её условия.
